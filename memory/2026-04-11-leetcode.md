## 1. Word Search
**LeetCode #79** | Pattern: Backtracking / DFS on Grid

### Problem
Given an `m x n` board of letters and a word `word`, return `True` if `word` exists in the grid. The word can be constructed from letters of sequentially adjacent cells (horizontally or vertically neighboring). A cell may not be used more than once in the same word.

### Solution

```python
from typing import List

def exist(board: List[List[str]], word: str) -> bool:
    """
    Backtracking with pruning. For each cell that matches word[0],
    start a DFS. Backtrack by undoing the mark on each step.
    """
    rows, cols = len(board), len(board[0])

    def dfs(r: int, c: int, i: int) -> bool:
        """
        Returns True if word[i:] can be formed starting from board[r][c].
        i = index of the next character we need to match in word.
        """
        # Base: matched all characters
        if i == len(word):
            return True

        # Bounds + mismatch check
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return False
        if board[r][c] != word[i]:
            return False

        # Mark cell as visited — prevents reuse within this path
        board[r][c] = "#"  # placeholder (sentinel)

        # Explore 4 directions
        found = (
            dfs(r + 1, c, i + 1) or
            dfs(r - 1, c, i + 1) or
            dfs(r, c + 1, i + 1) or
            dfs(r, c - 1, i + 1)
        )

        # Backtrack: restore cell for other paths
        board[r][c] = word[i]

        return found

    # Try every cell as a starting point (only those matching word[0])
    for r in range(rows):
        for c in range(cols):
            if board[r][c] == word[0]:
                if dfs(r, c, 0):
                    return True
    return False
```

### Key Insights
- **Backtracking is the core pattern**: mark → recurse → unmark (restore).
- Mark with a sentinel `#` instead of a separate `visited` set — saves O(m×n) space.
- Pruning: only start DFS from cells matching `word[0]`; DFS itself returns early on any character mismatch.
- Short-circuit `or` in the explore step means Python stops as soon as `found = True`.

### Complexity
| | Time | Space |
|---|---|---|
| Worst case | O(m × n × 4^L) — m×n cells, 4 directions, L=word length | O(L) — recursion depth, at most word length |

> Note: In practice, the real bound is much better because most branches prune early.

## 2. Pacific Atlantic Water Flow
**LeetCode #417** | Pattern: Multi-Source BFS / DFS (reverse flow)

### Problem
Given an `m x n` matrix of heights, water can flow from a cell to its neighbor if the neighbor's height is `≥` current height. The Pacific Ocean touches the top and left edges; the Atlantic Ocean touches the bottom and right edges. Return all cells from which water can flow to **both** oceans.

### Solution

```python
from typing import List

def pacific_atlantic(matrix: List[List[int]]) -> List[List[int]]:
    """
    Reverse multi-source BFS: instead of "where can water reach ocean",
    we ask "can ocean water reach here by flowing uphill?"

    For each ocean, start BFS/DFS from all adjacent cells and flow
    uphill. Cells reachable from BOTH oceans are the answer.
    """
    if not matrix or not matrix[0]:
        return []

    rows, cols = len(matrix), len(matrix[0])
    # Directions: up, down, left, right
    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    # Two boolean grids: cell reachable from Pacific? from Atlantic?
    pac_reachable = [[False] * cols for _ in range(rows)]
    atl_reachable = [[False] * cols for _ in range(rows)]

    def bfs(start_cells: List[tuple]) -> List[List[int]]:
        """BFS from multiple start cells flowing uphill."""
        visited = [[False] * cols for _ in range(rows)]
        queue = deque(start_cells)

        # Mark all start cells as visited immediately
        for r, c in start_cells:
            visited[r][c] = True

        while queue:
            r, c = queue.popleft()
            for dr, dc in directions:
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and not visited[nr][nc]:
                    # Water flows from (r,c) → (nr,nc) if nr/nc is higher or equal
                    if matrix[nr][nc] >= matrix[r][c]:
                        visited[nr][nc] = True
                        queue.append((nr, nc))
        return visited

    # Build start cells: left + top edge → Pacific; right + bottom edge → Atlantic
    pac_starts = [(0, c) for c in range(cols)] + [(r, 0) for r in range(1, rows)]
    atl_starts = [(rows - 1, c) for c in range(cols)] + [(r, cols - 1) for r in range(rows - 1)]

    pac_reachable = bfs(pac_starts)
    atl_reachable = bfs(atl_starts)

    # Intersection: cells reachable from BOTH oceans
    result = [
        [r, c]
        for r in range(rows)
        for c in range(cols)
        if pac_reachable[r][c] and atl_reachable[r][c]
    ]
    return result
```

### Key Insights
- **Reverse thinking is the key**: instead of flooding outward from every cell (O(m²n²)), start from the oceans and flow *backward* uphill. Each cell is visited at most twice → O(m×n).
- Two separate BFS passes, one per ocean, then intersection.
- Start cells include all edge cells (top row + left col for Pacific; bottom row + right col for Atlantic), but we deduplicate corners.
- The `≥` in the height comparison allows equal-height flow.

### Complexity
| Time | Space |
|---|---|
| O(m × n) — each cell visited at most twice (once per BFS) | O(m × n) — two visited grids + queue |

## 3. Accounts Merge
**LeetCode #721** | Pattern: Union-Find (Disjoint Set Union / DSU)

### Problem
Given a list of accounts where `accounts[i] = [name, email1, email2, ...]`, merge accounts with shared emails into a single account (same name). Return accounts as `[name, email1, email2, ...]` sorted alphabetically. Each email belongs to exactly one person, but a person may have multiple accounts.

### Solution

```python
from typing import List

class UnionFind:
    """Lightweight Union-Find with path compression + union by rank."""
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # path compression
        return self.parent[x]

    def union(self, x: int, y: int) -> None:
        px, py = self.find(x), self.find(y)
        if px == py:
            return
        # union by rank
        if self.rank[px] < self.rank[py]:
            px, py = py, px
        self.parent[py] = px
        if self.rank[px] == self.rank[py]:
            self.rank[px] += 1


def accounts_merge(accounts: List[List[str]]) -> List[List[str]]:
    """
    1. Map every email → its canonical DSU index.
    2. Union all email pairs within each account (they belong to same person).
    3. Group emails by their DSU root → one merged account per root.
    4. Attach name, sort emails, return.
    """
    email_to_idx = {}   # email string → 0..n-1 index
    idx_to_email = {}   # reverse map
    n = 0

    # Assign an index to every unique email
    for account in accounts:
        for email in account[1:]:
            if email not in email_to_idx:
                email_to_idx[email] = n
                idx_to_email[n] = email
                n += 1

    uf = UnionFind(n)

    # Union all emails in the same account
    for account in accounts:
        emails = account[1:]
        first_idx = email_to_idx[emails[0]]
        for email in emails[1:]:
            uf.union(first_idx, email_to_idx[email])

    # Group emails by DSU root
    from collections import defaultdict
    groups = defaultdict(list)  # root_idx → list of email indices
    for email, idx in email_to_idx.items():
        root = uf.find(idx)
        groups[root].append(email)

    # Build final answer
    result = []
    for account in accounts:
        name = account[0]
        root = uf.find(email_to_idx[account[1]])
        if root in groups:
            merged_emails = sorted(groups.pop(root))
            result.append([name] + merged_emails)

    # Handle any remaining (no corresponding account name)
    # (In this problem structure, every email maps to some account already)
    return result
```

### Simpler Alternative — No DSU Class

```python
def accounts_merge_simple(accounts: List[List[str]]) -> List[List[str]]:
    """
    Email-graph approach without formal DSU class.
    Build graph of shared emails, then DFS to collect connected components.
    """
    from collections import defaultdict

    # Build email → list of account indices
    email_to_accounts = defaultdict(list)
    for i, account in enumerate(accounts):
        for email in account[1:]:
            email_to_accounts[email].append(i)

    # Build adjacency: two accounts share an edge if they have a common email
    graph = defaultdict(set)
    for email, acc_list in email_to_accounts.items():
        for i in range(len(acc_list)):
            for j in range(i + 1, len(acc_list)):
                graph[acc_list[i]].add(acc_list[j])
                graph[acc_list[j]].add(acc_list[i])

    visited = [False] * len(accounts)
    merged = []

    def dfs(acc_idx: int, emails: set):
        visited[acc_idx] = True
        for email in accounts[acc_idx][1:]:
            emails.add(email)
        for neighbor in graph[acc_idx]:
            if not visited[neighbor]:
                dfs(neighbor, emails)

    for i, account in enumerate(accounts):
        if not visited[i]:
            emails = set()
            dfs(i, emails)
            merged.append([account[0]] + sorted(emails))

    return merged
```

### Key Insights
- **Union-Find is the natural fit**: emails that appear together in an account must be merged. DSU gives O(α(n)) ≈ O(1) amortized find/union.
- Alternative DFS/graph approach also works — builds an email-to-account index, then finds connected components via the account graph.
- Email deduplication across accounts is handled automatically by the email→index map (DSU) or the email set (DFS).
- Path compression + union by rank keeps DSU amortized near O(1).

### Complexity
| | Time | Space |
|---|---|---|
| O(n α(n)) ≈ O(n) — n = total emails | O(n) — maps + DSU arrays |

> Both approaches (DSU and DFS-graph) are O(m × k log(k)) where m=accounts, k=avg emails per account, dominated by the sort step.
